# Private draft threat review

Date: 2026-10-07. Scope: the approved private Business/Listing Draft/Preview backend in [ADR 0008](../adr/0008-private-listing-drafts.md). This is a source threat review and verification map, not an independent penetration test or production acceptance. Exact executed results belong in the delivery evidence. The [P0.4 threat review](P0.4-THREAT-MODEL.md) still governs authentication; no provider, session policy or ingress assumption is relaxed here.

## Boundaries and abuse cases

| Threat | Implemented boundary and required evidence | Residual risk / excluded capability |
| --- | --- | --- |
| Tenant hopping or forged owner/role claims | Resolve the current HUMAN account/session, workspace membership and explicit grants inside PostgreSQL transactions. Strict flat bodies reject authority fields. RLS and composite resource keys independently bind tenant ownership. Store and HTTP negative tests exercise actual restricted logins. | A compromised permitted account can exercise its actual grants. Professional invitation/delegation and bulk offboarding are separate reviewed workflows. |
| Organization affiliation confused with workspace authority | Existing organization affiliation grants no workspace permission; explicit workspace grants remain independent. Tests prove affiliation alone denies and revoked workspace access denies. | Removing affiliation alone does not revoke separately granted workspace access. A future offboarding command must explicitly manage its intended grants. |
| Personal bootstrap used to replenish removed authority | One explicit server-derived assignment, unique ownership path and exactly five initial grants commit atomically. Assignment reuse never reactivates membership or restores grants. Concurrent different-device and revoked-replay tests exercise this. | The migration/bootstrap owner has deliberate narrow capabilities; it cannot be used as an application login. General owner transfer or access repair is absent. |
| Stale authorization while waiting for locks | Existing account/session/grant locks order revocation against work. Recheck current database clock/session/grants after waits and before COMMIT. Test expiration during command and Business locks, canceled requests and reused pools. | An already authorized transaction may finish before a concurrent revocation obtains its conflicting lock. This is serialized ordering, not retroactive erasure of returned data. |
| Duplicate creation after a lost response | Immutable durable receipt scoped to User, context, workspace, operation and command UUID; normalized finite request fingerprint. Receipt, state and audit commit together. Real PostgreSQL tests simulate both lost committed response and uncommitted failure. | A new command identity requests a distinct draft. Clients must retain the original identity while reconciling uncertainty; receipt deletion must not silently shorten that guarantee. |
| Lost update, version regression or stale replay | Lock Business then Draft; require both expected versions. Advance only changed aggregates and reject stale versions. Creation replay returns its original IDs/initial versions; GET separately returns current fields. | PUT has no durable command receipt. After an uncertain update, reconcile with GET; a client cannot assume every failure rolled back. |
| Audit spoofing, secret dumping or unaudited writes | Finite typed actions/targets, session-bound HUMAN attribution, workspace/resource/session foreign keys, exact version-only metadata. Runtime ledger mutation is forbidden; reverse and deferred revision constraints reject mismatched or absent evidence. Negative direct-SQL tests prove constraints under restricted roles. | Privileged database operators remain outside append-only runtime protection. No legal retention, independent tamper-proof archive or audit browsing capability is asserted. |
| Malformed Unicode merges command identities | Reject malformed UTF-8 and unpaired JSON surrogates before decoding; normalize finite fields once. Bound descriptions by code points and validate the same fields durably in PostgreSQL. Transport/domain tests cover negative forms and maximum escaped Unicode. | Unicode confusables and text identifying a business remain user content. This private slice performs no public-content safety or anonymity certification. |
| Large body / lock contention denial of service | Finite 128KiB default body bound, text caps, configurable bounded timeouts, request cancellation and existing authentication abuse boundary. Tests reject oversized bodies and prove cancellation rollback. | No approved capacity/SLO exists. Per-account bootstrap serialization can contend; no public traffic/load acceptance has occurred. |
| Private representation reaches a public surface | Protected Preview is an explicit allowlist with current read permission, no-store and non-indexable responses. No public listing, HTML renderer, discovery index or asynchronous draft projection exists. Canary and response-contract tests inspect allowed fields. | Free text can reveal identity. A future public release must have its own disclosure, sanitization, cache and SEO eligibility policy; noindex is not an access control. |
| Database helper assumes superuser or leaks privileges | Fixed-search-path SECURITY DEFINER functions, PUBLIC execute revoked, forced RLS with explicit migration-owner helper policies. Runtime ownership validation includes listings; worker gets no draft grants. Migration test uses a non-superuser/no-BYPASSRLS owner. | Privileged migration/restore procedures must preserve function ownership and owner policies together. Production provisioning and restore are not tested by this slice. |
| Fake event processing or worker confused deputy | Protected Preview reads authoritative data synchronously. Existing WorkspaceNameChanged audit/outbox/consumer remain unchanged and fully tested; no draft event or worker privilege is added. | A later real asynchronous effect needs its own approved event schema and idempotent processing proof. |

## Evidence map and open gates

The concrete adversarial suites are [store/transaction tests](../../internal/store/listingdrafts_postgres_test.go), [HTTP restricted-role tests](../../internal/httpapi/listingdrafts_integration_test.go), [transport tests](../../internal/httpapi/listingdrafts_test.go), [Unicode decoding tests](../../internal/httpapi/jsonencoding_test.go), [domain tests](../../internal/listings/drafts_test.go) and [upgrade/owner tests](../../db/migrations/draft_upgrade_test.go). Test source existence is not a passing result. Run all [applicable quality gates](../operations/QUALITY-GATES.md) with required real PostgreSQL integration and inspect their output, followed by committed clean-checkout CI.

Provider conformance, privacy/purpose/retention, HTTPS ingress, named operational ownership, capacity budgets, production recovery and client integration remain open. No real business reports, photos, personal customer data, publication or cloud resources are admitted through this package. The [runbook](../operations/PRIVATE-DRAFTS.md) states recovery, uncertain COMMIT and receipt lifecycle boundaries.
