API configuration must explicitly select unavailable `disabled` or complete `oidc`; no development identity or silent fallback.
5. **Provider decision:** Auth0 EU remains the preferred conditional candidate in [the researched proposal](../architecture/P0.4-PROVIDER-OPTIONS.md). It is not a purchased/created/configured tenant. No SDK/vendor permission metadata binds the domain. Initial adapter uses RS256 and client_secret_basic; chosen client/assurance/revocation behavior must be proven in an approved synthetic sandbox.
6. **Session policy:** 256-bit opaque cookie, hash-only persistence; eight-hour absolute from verified authentication, fifteen-minute idle from committed workspace activity. Introspection/failed/public requests do not extend idle. Both expiries require fresh interactive authentication, max_age=0, signed auth_time and sixty-second external-clock allowance. Five-minute single-use browser-bound flows. No provider refresh token or offline_access. Current/all-local-session revocation is atomic; provider SSO is separate. Account switching requires logout first.
7. **Principal model:** immutable internal principal, HUMAN/SERVICE, human User where applicable, exact provider/issuer/subject, authentication time, session and credential provenance. Assurance is explicitly UNKNOWN until a reviewed provider interpretation exists; arbitrary claims never reach workspace rules.
8. **Authorization model:** default deny, live PostgreSQL account/session/membership/permission checks within each workspace transaction, transaction-local RLS scope, lock ordering with revocation, and no production actor-ID shortcut. Unknown/inaccessible resources share 404; missing credentials 401, CSRF 403, dependency uncertainty 503, optimistic conflict 409.
9. **Permission model:** only workspace.read and workspace.update. Reader and Editor templates resolve to scoped grants; update also requires read. Templates create neither membership nor access. No new role/member administration workflow was invented.
